# CL-Logs

Анализатор логов с консольным меню и графическим интерфейсом на Tk. Можно разобрать файл целиком или следить за новыми строками. В каталоге `Test logs` есть примеры для обоих интерфейсов.

## Запуск

Для запуска нужен Python 3.10 или новее. Графический интерфейс также использует Tk 8.6 или новее. Выполните команды из каталога проекта.

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 main.py
```

В терминале консоль работает в одном окне. Стрелки перемещают выделение, Enter открывает пункт или исходную строку, Esc возвращает назад. В главном меню клавиши A, M и S открывают анализ, мониторинг и настройки. Можно выбрать пример из проекта или ввести путь к своему файлу.

В журнале F переключает все записи, ошибки с предупреждениями и отмеченные опасными строки. Мониторинг читает новые строки с конца файла. В таблице доступны последние 2 000 записей, а счётчики охватывают весь сеанс.

В консоли используется тема «Янтарь». При открытии экрана символы за полсекунды складываются в текст. Эффект можно посмотреть в [анимированном примере](screenshots/reveal.gif).

Графический интерфейс запускается командой `python3 gui.py`. В поставляемом `settings.json` все уровни опасности отключены. Чтобы помечать предупреждения, ошибки и критические события, выберите восстановление стандартных уровней в настройках анализа.

## Маскировка данных

При анализе файлов и мониторинге распознанные конфиденциальные значения автоматически заменяются на `******`. Маскировка применяется до разбора записи, поэтому она действует и в представлении исходной строки, и в уведомлениях.

Правила охватывают пароли, токены, API-ключи, приватные PEM-ключи, заголовки авторизации и cookie, а также распознаваемые адреса электронной почты, IP-адреса, номера телефонов и платёжных карт. Секреты в полях JSON, параметрах URL и парах «ключ — значение» распознаются по имени поля или формату значения. Для произвольных значений без метки распознавание зависит от формата.

Мониторинг ждёт перевода строки перед разбором новой записи. При запуске он читает предыдущие строки для продолжения маскировки открытых многострочных блоков. Маскировка продолжается, если такой блок пересекает границу ротации или усечения файла.

При ротации мониторинг дочитывает переименованный журнал и продолжает с начала нового файла, когда исходный путь снова появляется. При обнаружении усечения чтение возобновляется с начала файла. Если между проверками файл сменился несколько раз, часть записей может быть пропущена.

Для формата Docker json-file маскировка многострочных блоков учитывает поток stdout или stderr и идентификатор контейнера, если он указан.

## Уведомления

Для отправки задайте переменную окружения `CL_LOGS_NOTIFICATION_URL` с базовым HTTP(S)-адресом своего сервера перед запуском. В настройках уведомлений укажите выданный сервером `user_hash`. Приложение использует маршруты `/` для проверки соединения, `/send` для сообщения и `/send_email` для дополнительного письма при уровне `ERROR`.

Получатель и выбор пользователя сохраняются в локальном файле `user_config.json` в текущем рабочем каталоге. Этот файл исключён из Git.

В интерактивном терминале и графическом интерфейсе уведомления отправляются в фоне по одному. В очереди помещается 128 ожидающих сообщений. Если очередь заполнена, новая запись по-прежнему появляется в журнале, а счётчик пропущенных уведомлений увеличивается. При выходе из терминального журнала или закрытии приложения ожидающие отправки отменяются. Уже начавшийся запрос может завершиться.
